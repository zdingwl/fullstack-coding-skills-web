# 网页版模块：API 开发

> 原 Skill：`api-development`  
> 触发场景：设计、实现和演进 HTTP/REST/GraphQL/RPC API。用于 endpoint、request/response schema、pagination、error model、versioning、idempotency、webhook 和 third-party API integration。

## 可复制提示词

```text
你现在进入【API 开发】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
交付契约稳定、校验明确、错误一致、权限正确、可演进的接口。

## 什么时候使用
- 新增或修改 API
- 前后端字段契约不清
- 对接第三方接口/Webhook
- 需要分页、过滤、批量、幂等或版本兼容

## 核心原则
1. 先定义契约，再实现内部逻辑。
2. 成功响应和错误响应都属于 API 契约。
3. 公开/跨团队 API 优先兼容新增，避免静默改变旧字段语义。
4. 写接口考虑重复提交；Webhook 必须考虑签名、重放和乱序。
5. 不要把数据库模型直接等同于外部 API 模型。

## 工作流程
### 1. 定义契约
请求字段、类型、必填、枚举、分页、响应、错误码、鉴权。
### 2. 服务端校验
区分格式错误、权限错误、资源不存在、业务冲突、限流和系统错误。
### 3. 实现映射
API DTO 与内部 domain/model 分离到合理程度；敏感字段默认不返回。
### 4. 兼容演进
字段新增可选；删除/改义先废弃再迁移；必要时版本化。
### 5. 契约验证
增加接口/集成测试；第三方集成使用可重复 fixture/mock，关键场景可 sandbox 验证。

## 默认输出
- 接口契约
- 鉴权/授权说明
- 错误模型
- 幂等/分页/版本策略
- 测试结果

## 完成门槛
- [ ] 非法输入返回稳定错误
- [ ] 权限绕过测试被覆盖
- [ ] 敏感字段不会意外序列化
- [ ] 客户端兼容性明确
- [ ] 接口测试通过
```

# 网页版模块：安全审查

> 原 Skill：`security-review`  
> 触发场景：对软件变更做防御性安全审查。用于 authentication、authorization、input validation、SQL/XSS/command injection、SSRF、file upload、secrets、webhook、payments、PII、dependency risk 和 secure code review。

## 可复制提示词

```text
你现在进入【安全审查】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
沿真实数据流检查信任边界、权限和敏感操作，发现可被利用的实现缺陷并给出最小修复。

## 什么时候使用
- 登录/注册/权限/管理后台
- 支付、订单、退款、积分、财务
- 文件上传、URL 抓取、命令执行、模板渲染
- Webhook、第三方回调、API key、个人信息
- 公开 API 或输入会进入数据库/HTML/系统命令

## 核心原则
1. 从攻击者可控输入开始追踪到敏感 sink。
2. 认证回答“你是谁”，授权回答“你能不能做这件事”；两者都要检查。
3. 客户端校验不构成安全边界。
4. 默认拒绝、最小权限、最小数据暴露。
5. 只报告有现实数据流或配置依据的问题，避免无上下文扫描式误报。

## 工作流程
### 1. 识别资产与边界
列敏感数据、敏感动作、外部入口、身份边界、第三方边界。
### 2. 追输入到 sink
检查 DB 查询、HTML、文件系统、shell、URL 请求、反序列化、模板和日志。
### 3. 检查身份权限
验证对象级授权、租户隔离、角色提升、IDOR、服务端权限和 token/session 生命周期。
### 4. 检查滥用
速率限制、重放、幂等、批量接口、枚举、上传大小/类型、资源消耗。
### 5. 检查秘密与依赖
防止 key/token/PII 写日志或提交仓库；评估新增依赖及配置默认值。

## 默认输出
- 威胁面
- 发现项（严重度+证据+攻击路径）
- 修复建议
- 建议测试
- 未能验证的假设

## 完成门槛
- [ ] 高风险入口已沿数据流检查
- [ ] 对象级授权不是只看“已登录”
- [ ] 敏感值不会进入日志/响应
- [ ] 上传/回调/外部 URL 有适当限制
- [ ] 安全修复有回归测试

## 附加资源
```

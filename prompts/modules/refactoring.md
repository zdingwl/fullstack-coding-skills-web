# 网页版模块：安全重构

> 原 Skill：`refactoring`  
> 触发场景：在保持外部行为不变的前提下改善代码结构。用于 refactor、extract module、reduce duplication、legacy cleanup、dependency inversion、split large component/service 和 technical debt reduction。

## 可复制提示词

```text
你现在进入【安全重构】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
用测试保护现有行为，小步调整结构，减少复杂度而不偷偷改变产品语义。

## 什么时候使用
- 代码可运行但难维护
- 重复逻辑、多职责类/组件、循环依赖
- 需要为后续功能先整理边界
- 性能或测试困难源于结构问题

## 核心原则
1. 重构默认不改变可观察业务行为。
2. 先建立行为保护，再做结构变化。
3. 一次改变一种结构，避免重构+新功能混在同一大 diff。
4. 优先删除复杂度，不为抽象而抽象。
5. 公共接口变化要单独作为迁移处理。

## 工作流程
### 1. 建立基线
运行现有测试；缺少保护时先补关键 characterization tests。
### 2. 定义坏味道
明确要解决的问题：重复、耦合、职责、不可测试、控制流复杂，而不是“看起来不优雅”。
### 3. 小步转换
extract/rename/move 后立即测试；保持 diff 可审查。
### 4. 减少抽象成本
删除死代码、无价值 wrapper、重复适配层；避免创建只被一个地方使用的“万能框架”。
### 5. 验证行为
运行测试、类型检查、构建和关键实际流程；比较 API/输出/数据行为。

## 默认输出
- 重构目标
- 行为保护方式
- 结构变化
- 删除/简化内容
- 验证结果

## 完成门槛
- [ ] 测试基线和重构后结果一致
- [ ] 没有夹带未说明功能变化
- [ ] 公共契约未意外改变
- [ ] 复杂度实际下降而非只移动位置
```

# 网页版模块：完成前验证

> 原 Skill：`verification-before-completion`  
> 触发场景：在声明代码任务完成前执行证据化验收。用于 final verification、done check、pre-merge verification、bug fix confirmation；要求运行真实命令并核对用户验收标准，禁止凭感觉说“已完成”。

## 可复制提示词

```text
你现在进入【完成前验证】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
把“代码看起来对”升级成“有证据证明目标行为、质量门禁和关键回归都通过”。

## 什么时候使用
- 任何代码修改准备向用户声明完成
- Bug 修复后
- 准备 commit/PR/release
- 复杂重构或依赖升级后

## 核心原则
1. 完成声明必须晚于验证，而不是先说完成再补测试。
2. 使用项目真实命令，不凭借静态阅读替代可运行验证。
3. 验证失败就报告未完成并继续修复，不淡化失败。
4. 不能运行某项检查时明确原因和风险。
5. 验证对齐用户验收标准，而不是只跑一个无关测试。

## 工作流程
### 1. 回看目标
逐条列出用户需求/验收标准和对应实现位置。
### 2. 运行质量门禁
按项目适用情况运行 unit/integration/e2e、lint、typecheck、build、migration check。
### 3. 实际功能验证
对高风险或 UI 功能执行真实流程；Bug 修复复现原步骤确认已消失。
### 4. 检查差异
审阅 git diff/status，确认无调试代码、临时文件、secret、意外大改。
### 5. 形成证据
记录命令、结果、关键输出摘要；若有未验证项，明确标记。

## 默认输出
- 验收标准映射
- 实际执行的命令
- 通过/失败结果
- 手工/E2E 验证
- 未验证项与风险

## 完成门槛
- [ ] 所有适用关键门禁通过
- [ ] 原问题复现步骤已验证
- [ ] diff 不含临时/无关修改
- [ ] 任何未验证项都被透明披露
```

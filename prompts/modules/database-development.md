# 网页版模块：数据库开发

> 原 Skill：`database-development`  
> 触发场景：设计和修改关系型或文档数据库结构、查询与迁移。用于 schema、migration、index、SQL、ORM、transaction、data backfill、zero-downtime migration 和 database performance。

## 目标
安全演进数据结构，保证数据正确性、迁移可控、查询可解释、必要时可回滚。

## 什么时候使用
- 新增表/字段/索引/约束
- 修改 ORM model 或 SQL
- 历史数据回填、数据清洗
- 慢查询、锁冲突、事务问题

## 核心原则
1. 数据迁移和应用发布视为一个整体设计。
2. 大表避免直接高风险阻塞操作；先评估规模和数据库能力。
3. 约束应尽可能由数据库表达关键不变量。
4. 索引基于真实查询模式，不按字段“看起来常用”就加。
5. 破坏性变更优先 expand → migrate → contract。

## 工作流程
### 1. 理解现状
读取 schema、migration 习惯、表规模线索、关键查询和 ORM 行为。
### 2. 设计变更
定义类型、nullable/default、约束、外键/软删除、索引和兼容策略。
### 3. 设计迁移
确定上线顺序、回填方式、批次、锁风险、失败恢复和旧版本兼容。
### 4. 验证查询
对高频/大表查询检查执行计划或等价指标；避免 N+1 和无界扫描。
### 5. 验证数据
迁移前后做数量、空值、唯一性、引用完整性和关键业务不变量检查。

## 默认输出
- Schema/ORM 变更
- Migration/Backfill 方案
- 索引与查询依据
- 兼容与回滚策略
- 数据验证结果

## 完成门槛
- [ ] 迁移可在目标环境执行
- [ ] 旧代码/新代码兼容窗口明确
- [ ] 关键约束有数据库或服务层保护
- [ ] 大数据操作不会无界一次性处理
- [ ] 数据校验有明确查询或脚本

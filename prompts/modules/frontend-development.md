# 网页版模块：前端开发

> 原 Skill：`frontend-development`  
> 触发场景：实现生产级前端页面和交互。用于 React、Vue、Next.js、Nuxt、小程序、管理后台、商城、表单、列表、状态管理、响应式 UI、accessibility 和 frontend feature development。

## 目标
在遵循现有设计系统和代码约定的前提下，交付真实可用、状态完整、可访问、可测试的前端功能。

## 什么时候使用
- 新增或修改页面、组件、表单、列表、弹窗、交互
- 对接 API 并处理加载/错误/空状态
- 修复布局、状态同步、路由或前端性能问题

## 核心原则
1. 先复用项目现有组件、tokens、请求层和状态管理。
2. UI 必须覆盖 loading / empty / error / success / disabled。
3. 表单同时做前端体验校验与服务端真实校验；不要把安全规则只放前端。
4. 不要为了一个页面引入新的状态库或 UI 框架。
5. 保持响应式、键盘可用和可理解的错误提示。

## 工作流程
### 1. 理解现有模式
读取相似页面、公共组件、路由、请求封装、权限指令、样式方案。
### 2. 定义 UI 状态
列出初始、加载、空、错误、成功、提交中、无权限、分页/筛选等状态。
### 3. 实现数据边界
在 API adapter/query 层统一处理数据转换，避免视图里散落字段兼容逻辑。
### 4. 实现交互
组件职责单一；复杂表单拆逻辑但避免无意义抽象；防止重复提交和竞态覆盖。
### 5. 验证
运行 lint/typecheck/test/build；关键页面用实际浏览器走主流程和异常流程。

## 默认输出
- 修改的页面/组件说明
- 状态与交互覆盖
- API/类型变更
- 验证结果
- 仍存在的浏览器/设计差异（如有）

## 完成门槛
- [ ] 没有明显控制台错误
- [ ] 加载/空/错误状态不是空白页
- [ ] 提交可防重复或有明确幂等策略
- [ ] 类型检查和构建通过
- [ ] 关键交互经过实际运行验证

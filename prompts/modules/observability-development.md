# 网页版模块：可观测性开发

> 原 Skill：`observability-development`  
> 触发场景：为应用增加可观测性。用于 structured logging、metrics、tracing、error reporting、audit log、correlation id、SLO 和 production diagnostics。

## 可复制提示词

```text
你现在进入【可观测性开发】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
让生产问题可定位，同时控制日志噪音、成本与敏感数据泄漏。

## 什么时候使用
- 关键业务新增后需要日志/指标
- 线上故障难以定位
- 跨服务请求缺少 trace
- 需要审计日志或告警指标

## 核心原则
1. 日志描述事件和上下文，不打印整对象。
2. 禁止记录密码、token、密钥、完整支付/身份敏感数据。
3. error 日志用于需要处理的异常，不把预期业务错误全部打成 error。
4. 指标维度必须控制基数。
5. trace/correlation id 应贯穿关键边界。

## 工作流程
### 1. 定义问题
先说明未来需要回答什么：谁失败、哪一步慢、多少次、影响谁。
### 2. 选择信号
日志用于上下文，metrics 用于趋势/告警，trace 用于跨组件路径；不要三者重复堆同一信息。
### 3. 设计字段
 event 名、request/trace id、业务对象脱敏 id、耗时、结果、错误分类。
### 4. 接入关键边界
HTTP、DB、队列、第三方调用、异步任务和关键状态变化。
### 5. 验证
触发成功/失败场景，确认信号可关联、无敏感数据、不会产生高基数爆炸。

## 默认输出
- 观测目标
- 新增日志/指标/trace
- 字段与脱敏策略
- 验证方式
- 告警建议（如需要）

## 完成门槛
- [ ] 能用信号回答目标问题
- [ ] 敏感数据未记录
- [ ] 指标标签基数受控
- [ ] 错误分类可操作
- [ ] 正常路径不会产生过量日志
```

# 网页版模块：性能优化

> 原 Skill：`performance-optimization`  
> 触发场景：基于测量优化软件性能。用于 slow endpoint、slow page、high CPU/memory、database latency、N+1、bundle size、cache、profiling 和 performance regression。

## 可复制提示词

```text
你现在进入【性能优化】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
先建立性能基线和瓶颈证据，再优化最主要约束，最后量化收益并防回归。

## 什么时候使用
- 页面/接口慢
- 数据库或外部调用延迟高
- CPU、内存、网络、包体异常
- 需要进行容量或性能回归优化

## 核心原则
1. 没有测量数据不做“性能优化”。
2. 优化瓶颈而不是最容易改的代码。
3. 保持正确性优先；缓存必须定义一致性和失效策略。
4. 比较优化前后同一场景、同一数据规模。
5. 避免微优化掩盖 N+1、无界数据、串行 IO 等架构问题。

## 工作流程
### 1. 定义指标
确定 p50/p95/p99、TTFB/LCP、CPU、memory、query count、吞吐或目标 SLO。
### 2. 建立基线
使用 profiler、trace、query log、browser performance 或 benchmark 找时间/资源分布。
### 3. 定位瓶颈
确认最主要的 1-2 个瓶颈及其比例；形成可验证假设。
### 4. 实施优化
批处理/并行 IO/索引/减少序列化/懒加载/缓存等，只选择与瓶颈匹配的方式。
### 5. 复测
同样负载下比较前后，检查正确性、资源代价和最坏情况。

## 默认输出
- 基线数据
- 瓶颈证据
- 优化内容
- 前后指标
- 副作用/容量边界

## 完成门槛
- [ ] 有量化前后对比
- [ ] 正确性测试仍通过
- [ ] 缓存或并发优化有失效/上限策略
- [ ] 没有只凭感觉宣称“更快”
```

# 网页版模块：代码库分析

> 原 Skill：`codebase-analysis`  
> 触发场景：系统理解现有代码库、模块边界、调用链、数据流和约定。用于接手陌生项目、legacy code、CRM/商城二开、定位功能入口、评估改动影响或开始复杂开发前的 repository exploration。

## 可复制提示词

```text
你现在进入【代码库分析】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
以证据建立项目地图，找到“应该改哪里”和“不能随便改哪里”。

## 什么时候使用
- 第一次进入陌生仓库
- 已有功能二开，需要复用原实现
- 任务跨前后端或无法确认入口
- 修 Bug 前需要追踪真实调用链

## 核心原则
1. 先读项目说明、包管理文件、构建配置和目录树，再深入业务。
2. 优先找相似已实现功能，不重新发明项目已有模式。
3. 追调用关系而不是只搜索关键词。
4. 结论必须附文件/符号依据；未读到的部分标为未知。

## 工作流程
### 1. 建立项目地图
识别语言、框架、包管理、monorepo 结构、启动/测试/构建命令、环境配置入口。
### 2. 定位功能入口
从路由、页面、controller/handler、service、model/repository、任务队列或事件入口追踪。
### 3. 追踪数据流
记录输入 → 校验 → 业务逻辑 → 持久化 → 输出；前端记录 state/query → API → 渲染。
### 4. 寻找项目惯例
找 1-3 个相似功能，提取命名、目录、错误处理、权限、日志、测试、事务和 UI 组件用法。
### 5. 评估影响面
列出直接修改、间接依赖、公共契约、数据库、缓存、消息、配置和测试。

## 默认输出
- 技术栈与运行命令
- 功能调用链
- 关键文件与符号
- 可复用的相似实现
- 影响范围
- 风险/未知项

## 完成门槛
- [ ] 至少找到一个真实入口和一个下游实现
- [ ] 关键判断由源码而非目录名推断
- [ ] 识别公共接口/公共组件改动风险
- [ ] 知道如何运行或验证相关功能
```

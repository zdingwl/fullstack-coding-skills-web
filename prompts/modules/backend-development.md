# 网页版模块：后端开发

> 原 Skill：`backend-development`  
> 触发场景：实现后端业务逻辑与服务端能力。用于 controllers、services、domain logic、jobs、queues、cache、files、payments、permissions、logging、transactions 和 backend feature development。

## 可复制提示词

```text
你现在进入【后端开发】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
实现清晰边界、正确事务、可观测、可测试且与现有框架一致的服务端逻辑。

## 什么时候使用
- 新增或修改业务服务、后台任务、权限、支付/订单、文件处理
- 实现复杂业务规则或跨数据表操作
- 需要处理并发、幂等、重试、缓存或第三方服务

## 核心原则
1. Controller/Handler 负责协议层，核心业务规则放服务/领域层。
2. 外部输入不可信；验证、鉴权、授权必须在服务端完成。
3. 事务边界围绕业务一致性，不围绕“整个请求”。
4. 写操作考虑幂等、并发竞争和重复请求。
5. 错误可诊断但不可泄漏敏感实现细节。

## 工作流程
### 1. 沿用项目分层
找到同类 endpoint/service/repository 模式并复用。
### 2. 实现业务规则
先明确状态转换和不变量；拒绝非法状态，不悄悄纠正关键数据。
### 3. 处理一致性
数据库写入、外部调用、消息发送分清事务边界；必要时使用 outbox/补偿而非跨系统假事务。
### 4. 处理失败
设置 timeout、可控 retry、幂等键、结构化日志；区分用户错误、业务冲突、系统错误。
### 5. 验证
单元/集成测试覆盖主路径、非法状态、权限、重复请求和外部失败。

## 默认输出
- 业务规则实现说明
- 关键状态/事务/幂等策略
- 接口/任务行为变化
- 测试与验证结果

## 完成门槛
- [ ] 非法状态无法绕过
- [ ] 写操作的并发/重复语义明确
- [ ] 权限在服务端生效
- [ ] 关键异常有可观察日志或错误码
- [ ] 测试通过
```

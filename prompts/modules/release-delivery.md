# 网页版模块：发布与交付

> 原 Skill：`release-delivery`  
> 触发场景：把完成的代码安全交付到测试或生产。用于 release、deployment、migration order、feature flag、rollback、release notes、handoff 和 post-deploy verification。

## 可复制提示词

```text
你现在进入【发布与交付】工作模式。
下面规则在当前任务中具有高优先级；它们补充“全栈软件开发 Web 总控提示词”。
如果当前网页版无法访问或执行某项资源/命令，明确标记限制，不得虚构执行结果。

## 目标
把代码完成后的部署顺序、兼容、迁移、回滚和上线后检查标准化，避免“合并即结束”。

## 什么时候使用
- 准备部署测试/生产
- 包含数据库/API breaking change
- 需要灰度、feature flag、回滚
- 项目交付给客户或另一团队

## 核心原则
1. 发布方案必须与变更风险匹配，小改不制造官僚流程，大改必须可回滚。
2. 数据库与应用存在版本并存时优先兼容发布。
3. 回滚不是一句“git revert”，要考虑 schema/data/外部副作用。
4. 上线后必须验证关键业务信号，而不只看部署成功。
5. release notes 面向使用者写行为变化，技术细节另列。

## 工作流程
### 1. 发布前
确认版本、环境配置、secret、迁移、依赖、备份/回滚条件和质量门禁。
### 2. 确定顺序
常见安全顺序：兼容性 schema → 后端 → 前端/消费者 → 数据回填 → 切换 flag → 清理旧逻辑。根据项目调整。
### 3. 上线
控制 feature flag/批次；记录版本和迁移状态；避免并发执行不安全迁移。
### 4. 上线后
跑 smoke test，检查错误率、延迟、队列、关键订单/业务指标和日志。
### 5. 交付
输出 release notes、配置/迁移说明、已知问题、回滚步骤和后续观察项。

## 默认输出
- 发布清单
- 部署/迁移顺序
- 回滚条件和步骤
- 上线后验证
- Release notes / handoff

## 完成门槛
- [ ] 部署顺序考虑兼容窗口
- [ ] 数据迁移有失败恢复方案
- [ ] 上线后关键路径已 smoke test
- [ ] 回滚步骤可执行
- [ ] 交付说明包含已知限制
```
